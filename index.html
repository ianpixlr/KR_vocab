How it works

Each day you get up to 10 new words (change it in Settings) plus any reviews that are due. Flip the card, then grade yourself honestly — the app schedules the next review using spaced repetition (SM‑2 style: roughly 1 → 3 → 8 → 20 days…). A word counts as mastered once its interval reaches 21 days.

Keyboard shortcuts

  • Space / Enter flip the card
  • 1 Again · 2 Hard · 3 Good · 4 Easy
  • P pronounce the word · E pronounce the example
  • Multiple-choice quiz: 1–4 pick an answer

Three ways to add words

  1. Manual form — Words tab → ＋ Add word. Edit or delete any word from the table.
  2. Import a file or paste — Words tab → Import / paste. Upload a .csv, .tsv or .json file, or copy cells straight out of Google Sheets / Excel (include the header row) and paste them. Download the template there to see the format.
  3. Sync URL (self-updating) — keep your list in a Google Sheet. In Sheets: File → Share → Publish to web → choose the sheet → Comma-separated values (.csv) → Publish, and copy the link. Paste it in Settings → Sync. Every time you open the app, new rows are added automatically. A GitHub “raw” CSV/JSON link works too (normal github.com/…/blob/… links are converted automatically).

Column format

id, korean, hanja, pos, meaning_en, example_ko, example_en, notes, related, unit, tags, date_added

  • Only korean and meaning_en are required; column order doesn't matter when there's a header row. Header aliases like word, english, meaning, example also work.
  • tags: separate with ; (e.g. travel;verbs). date_added: YYYY-MM-DD. Leave id blank and the app makes one.
  • Merging: matched by id or by Korean + meaning. Non-empty values from the import update the word; blank cells never erase anything. If you change a word's meaning in the sheet (and it has no id) it's treated as a new word.

About sync & opening the file directly

Sync works best when the app is hosted (e.g. GitHub Pages). When opened by double-clicking (file://), some browsers block network requests or treat the page as having no origin; Google Sheets and GitHub raw usually still work, but if you see a sync error, host the file or use Import instead. The source must allow cross-origin requests (Google “Publish to web” CSV and raw.githubusercontent.com do; a normal Google Drive file link does not).

Progress is stored per browser and per site address. If you move the app to a new URL or device, use Export backup → Import.
