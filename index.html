How it works

Each day you get up to 10 new words (change it in Settings) plus any reviews that are due. Flip the card, then grade yourself honestly — the app schedules the next review using spaced repetition (SM‑2 style: roughly 1 → 3 → 8 → 20 days…). A word counts as mastered once its interval reaches 21 days.

Keyboard shortcuts

  • Space / Enter flip the card
  • 1 Again · 2 Hard · 3 Good · 4 Easy
  • P pronounce the word · E pronounce the example
  • Multiple-choice quiz: 1–4 pick an answer
  • Stories: E show / hide English · Esc close the word popup, then back to the story list

Stories

Short graded reading in four stages, from simple dialogues to diary entries. A stage unlocks once you’ve read every story in the stages before it (or turn on Settings → Unlock all stories).

  • Korean first. Read the whole story in Korean. Tap a line or speech bubble to peek at just that line’s English, or press Show English (E) to show it under every line.
  • Dotted words are this story’s key vocabulary — tap one for its meaning. ✓ In your deck means it’s already in your flashcards. Story vocab comes into your deck through sync (the Vocab tab of your sheet).
  • The speaker button reads one line; ▶ Read whole story reads it all (dialogue speakers get different voices or pitch where your device allows).
  • Answer the Comprehension check; when every question is answered the story is marked as read (or press Mark as read). Get every question right for a small celebration.
  • Missed questions are remembered: the story shows ↻ N to review in the list. Open it, reread it, and the questions you missed are reset at the end (flagged Review) so you can try them again. A correct answer clears it from the review list.
  • Comprehension N% on each story card = your % correct on that story’s questions, from the comprehension check. The Progress tab lists it per story.

Question types

  • tf O/X — a statement about the story; answer 맞아요 or 틀려요.
  • mcq 선택 — pick the right answer from 2–4 options.
  • who 누가 — a quoted line: who said it? (dialogues)
  • order 순서 — tap 3–4 events in the order they happened.
  • blank 빈칸 — a sentence from the story with ___; pick the missing word (choices come from the story’s word list and your deck).
  • short 대답 — answer in your head or out loud, press Show answer (답 보기 in the quiz), compare with the model answer, then mark yourself right or wrong.

Adding a story in the Google Sheet

Use the Stories tab, one row per element, with columns story_id, stage, order, theme, format, title_ko, title_en, type, speaker, ko, en, word_ref, notes, qtype. Give the new story a new id (e.g. st-17), its stage, and number order 1, 2, 3… The type column says what each row is:

  • meta — one per story: stage, theme, format (dialogue / prose / mixed), title_ko, title_en; en = a one-line summary.
  • line — one dialogue line (speaker = name) or one prose sentence (speaker blank); ko + en. Put ¶ in notes to start a new paragraph.
  • vocab — ko = dictionary form, en = meaning, word_ref = the Vocab tab id if the word is in your bank, notes = in story: form1, form2 — usage note (the forms listed are what gets underlined).
  • grammar — ko = pattern, en = explanation plus the example from the story.
  • question — ko = the question in Korean, en = its English (hidden until asked for), notes = answer in Korean | answer in English, qtype = one of the types above, word_ref = optional L5 = the story line the answer comes from (shown after answering; the app guesses if blank). By type:
    • tf: ko = the statement; notes 맞아요 | True or 틀려요 | False — why.
    • mcq: options in speaker separated by / ; the Korean answer must match one option exactly.
    • who: ko = “quoted line” 누가 말했어요?; speaker = the names separated by / (blank = the story’s speakers); answer = the name.
    • order: speaker = 3–4 events separated by / in the correct order (the app shuffles them).
    • blank: ko = a story sentence with ___ where a word from the story’s vocab list was; answer = that word, exactly as it fits the blank.
    • short: answer = a model answer.
    A row with no qtype is treated as mcq if it has options, otherwise short. Aim for 4–6 questions per story.

Publishing: nothing extra to paste — the sync link in Settings does both. Publish the sheet with File → Share → Publish to web → Entire document → Comma-separated values (.csv); the app fetches the Vocab tab from your link and the Stories tab (gid 1019870171) from the same sheet. Edits show up next time the app opens (Google can take a few minutes to refresh). If you ever keep stories elsewhere, use Settings → Stories → Advanced: Stories CSV URL override.

Three ways to add words

  1. Manual form — Words tab → ＋ Add word. Edit or delete any word from the table.
  2. Import a file or paste — Words tab → Import / paste. Upload a .csv, .tsv or .json file, or copy cells straight out of Google Sheets / Excel (include the header row) and paste them. Download the template there to see the format.
  3. Sync URL (self-updating) — keep your list in a Google Sheet. In Sheets: File → Share → Publish to web → Entire document → Comma-separated values (.csv) → Publish, and copy the link (a link to just the Vocab tab, …pub?gid=…&single=true&output=csv, works too). Paste it in Settings → Sync. The same link also loads your Stories tab. Every time you open the app, new rows are added automatically. A GitHub “raw” CSV/JSON link works too (normal github.com/…/blob/… links are converted automatically).

Column format

id, korean, hanja, pos, meaning_en, example_ko, example_en, notes, related, unit, tags, date_added

  • Only korean and meaning_en are required; column order doesn't matter when there's a header row. Header aliases like word, english, meaning, example also work.
  • tags: separate with ; (e.g. travel;verbs). date_added: YYYY-MM-DD. Leave id blank and the app makes one.
  • Merging: matched by id or by Korean + meaning. Non-empty values from the import update the word; blank cells never erase anything. If you change a word's meaning in the sheet (and it has no id) it's treated as a new word.

About sync & opening the file directly

Sync works best when the app is hosted (e.g. GitHub Pages). When opened by double-clicking (file://), some browsers block network requests or treat the page as having no origin; Google Sheets and GitHub raw usually still work, but if you see a sync error, host the file or use Import instead. The source must allow cross-origin requests (Google “Publish to web” CSV and raw.githubusercontent.com do; a normal Google Drive file link does not).

Progress is stored per browser and per site address. If you move the app to a new URL or device, use Export backup → Import.
